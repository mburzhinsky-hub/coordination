## Быстрый запуск одним двойным кликом

Если нужна схема максимально близкая к обычной программе, используйте:

```text
INSTALL_AND_START_DASHBOARD.cmd
```

Этот файл:
- скачивает dashboard в `%LOCALAPPDATA%\ITO-Coordination\coordination`, если он еще не установлен;
- проверяет Node.js и при необходимости пытается поставить Node.js LTS через winget;
- создает общий логин `ito` и случайный сильный пароль;
- выбирает свободный порт 8787–8797;
- создает локальную конфигурацию;
- добавляет правило Windows Firewall для локальной сети и Tailscale;
- запускает сервер в фоне;
- ставит автозапуск при входе в Windows;
- открывает dashboard в браузере;
- создает файл `SHARE_WITH_COLLEAGUE.txt` со ссылкой, логином и паролем;
- копирует ссылку для коллеги в буфер обмена.

Если репозиторий уже скачан, достаточно двойного клика по:

```text
START_DASHBOARD.cmd
```

Для работы в одной локальной сети Tailscale не обязателен. Для доступа из разных сетей рекомендуется Tailscale.

# Общий синхронный доступ к ИТО Coordination

## Архитектура

Один постоянно включенный компьютер работает как сервер:

- Node.js раздает dashboard;
- общие snapshots, «Кто где», настройки и исходные выгрузки хранятся в `shared-data/`;
- оба пользователя открывают один и тот же адрес;
- браузеры проверяют ревизию сервера каждые 5 секунд и автоматически подтягивают изменения;
- GitHub Pages остается резервной локальной версией и не является общей базой.

Сервер использует HTTP Basic Auth. Не публикуйте порт 8787 напрямую в интернет. Для удаленного доступа используйте Tailscale.

## 1. Требования

На серверном компьютере:

- Windows 10/11;
- Git;
- Node.js 18+;
- репозиторий `mburzhinsky-hub/coordination`;
- для доступа из разных сетей — Tailscale.

Проверка Node.js:

```powershell
node -v
```

## 2. Обновить репозиторий

```powershell
cd C:\путь\к\coordination
git pull
```

## 3. Создать локальную конфигурацию

Из корня репозитория:

```powershell
powershell -ExecutionPolicy Bypass -File .\server\setup-windows.ps1
```

Скрипт попросит:

- логин;
- пароль не короче 10 символов;
- порт, по умолчанию 8787.

Файл `server/config.local.json` находится в .gitignore и не отправляется в GitHub.

## 4. Запустить сервер

```powershell
powershell -ExecutionPolicy Bypass -File .\server\run-shared.ps1
```

Локальная проверка:

```text
http://localhost:8787
```

Браузер попросит логин и пароль.

В верхней части dashboard должен появиться зеленый индикатор:

```text
Общий сервер
```

Если отображается `Локально`, dashboard не подключился к API.

## 5. Перенести существующую историю с GitHub Pages

IndexedDB привязан к домену, поэтому база GitHub Pages не может автоматически читаться локальным сервером.

### На старом GitHub Pages

Откройте:

```text
https://mburzhinsky-hub.github.io/coordination/migration.html
```

Нажмите `Скачать базу`.

Будет получен файл вида:

```text
coordination-backup-2026-10-07.json
```

### На локальном сервере

Откройте:

```text
http://localhost:8787/migration.html
```

Авторизуйтесь, выберите скачанный JSON и нажмите `Импортировать`.

После завершения вернитесь на:

```text
http://localhost:8787
```

и обновите страницу.

## 6. Доступ второго пользователя

### Вариант A — одна локальная сеть

На серверном ПК:

```powershell
ipconfig
```

Найдите IPv4, например `192.168.1.42`.

На втором ПК:

```text
http://192.168.1.42:8787
```

Если Windows Firewall спросит разрешение для Node.js, разрешайте доступ только для частных сетей.

### Вариант B — Tailscale, рекомендуемый

Установите Tailscale на оба компьютера и подключите их к одной tailnet.

После этого используйте Tailscale IP серверного ПК:

```text
http://100.x.y.z:8787
```

или MagicDNS-имя:

```text
http://имя-компьютера:8787
```

Не создавайте port forwarding на домашнем или офисном роутере.

## 7. Автозапуск

После успешной ручной проверки:

```powershell
powershell -ExecutionPolicy Bypass -File .\server\install-autostart-windows.ps1
```

Скрипт создаст launcher в пользовательской папке Windows Startup.

Сервер будет автоматически запускаться после входа пользователя в Windows.

Лог:

```text
shared-server.log
```

## 8. Где хранятся данные

По умолчанию:

```text
coordination\shared-data\
```

Внутри отдельные каталоги:

- `snapshots`;
- `presence`;
- `sources`;
- `settings`;
- `meta.json` с номером общей ревизии.

`shared-data/` исключен из Git.

## 9. Резервная копия

Откройте:

```text
http://localhost:8787/migration.html
```

и нажмите `Скачать базу`.

Храните JSON-копию отдельно от серверного компьютера.

Дополнительно можно периодически копировать всю папку `shared-data` при остановленном сервере.

## 10. Ежедневная работа

Оба пользователя открывают общий адрес.

Любой из них может:

1. загрузить новый Bitrix XLS;
2. заполнить «Кто где»;
3. открыть задачи и проекты.

Запись попадает на серверный ПК. Второй браузер обычно увидит изменения в течение 5 секунд.

Одновременно редактировать «Кто где» нежелательно: если два человека сохранят один и тот же дневной контекст почти одновременно, последняя запись победит.

## 11. Обновление кода

На серверном компьютере:

1. остановите Node.js через `Ctrl+C`;
2. выполните:

```powershell
git pull
```

3. снова запустите `run-shared.ps1`.

Данные в `shared-data` от обновления Git не затрагиваются.

## 12. Безопасность

- не коммитьте `server/config.local.json`;
- не коммитьте `shared-data/`;
- не открывайте TCP 8787 на роутере в публичный интернет;
- используйте длинный уникальный пароль;
- для доступа вне локальной сети используйте Tailscale;
- делайте резервную копию базы;
- Windows-пользователь серверного ПК должен быть защищен паролем.

## 13. Диагностика

### Dashboard показывает «Локально»

Проверьте, что он открыт через адрес локального сервера, а не GitHub Pages.

Проверьте:

```text
http://localhost:8787/api/health
```

После авторизации должен вернуться JSON с `"shared": true`.

### Второй ПК не открывает страницу

Проверьте:

- серверный процесс работает;
- адрес и порт верны;
- Windows Firewall;
- оба устройства в одной LAN или одной Tailscale tailnet.

### После импорта не появились данные

Обновите `http://localhost:8787`. Если нужно, повторно откройте `migration.html` и скачайте server backup: в нем должны присутствовать snapshots.
