# Координация ИТО

Минималистичный ежедневный dashboard инженерно-технического отдела.

## Ежедневный сценарий

1. Откройте dashboard. Заголовок на экране **Сегодня** одной фразой говорит, что происходит в отделе.
2. Выгрузите задачи из Bitrix24 и перетащите файл (.xls) в окно или нажмите **Обновить**.
3. Dashboard проверит структуру выгрузки, сравнит срез с предыдущим и покажет, что изменилось.
4. Отметьте, кто где сегодня (офис, объект, удалённо, отпуск). Вчерашние значения подставляются сами.
5. Разберите **Входящие**: у каждой записи три хода — назначить, отложить, эскалировать — или отметить «готово».

Данные snapshot, нормализованные задачи, события, ручной контекст и отметки решений хранятся в IndexedDB текущего браузера (и в общем хранилище, если запущен shared-сервер). Сырые загруженные файлы сохраняются только для последних 14 snapshot.

Данные snapshot, нормализованные задачи, события и ручная матрица хранятся в IndexedDB текущего браузера. Сырые загруженные файлы сохраняются только для последних 14 snapshot.

## Основная модель

Dashboard разделяет:

- **Attention** — то, что требует действия сейчас;
- **Debt** — старый накопленный долг;
- **Live workload** — реальные активные задачи, где следующий ход принадлежит исполнителю.

Старые неизменные просрочки не конкурируют с новыми событиями за внимание. После 14/30 дней без движения они переходят в `chronic`/`legacy` debt и доступны в отдельном блоке.

Перенос дедлайна не считается закрытием просрочки. Исчезновение задачи из выгрузки имеет нейтральный статус, пока причина не известна.

## Проекты

Project identity определяется в первую очередь по родительской / базовой задаче Bitrix:

`Название базовой задачи` → `Базовая задача` → `Родительская задача` → `Проект / Группа`.

Контейнеры вида `ЦСН — техническая реализация`, `Музей имени Бахрушина — техническая реализация`, `Лужники — техническое сопровождение` используются как структура проекта и не учитываются как обычные рабочие задачи.

## Экраны

Навигация: боковая панель на компьютере, нижняя панель на телефоне. Прямые адреса: `#/today`, `#/inbox`, `#/people`, `#/projects`, `#/horizon`, `#/debt`, `#/history`, `#/tv`.

| Экран | Что отвечает |
| --- | --- |
| **Сегодня** | Заголовок дня, три истории (что горит, что застряло, куда растёт долг), четыре показателя с динамикой, «Кто где», «Решить сегодня», проекты, «Что изменилось». |
| **Входящие** | Очередь решений: приёмки старше 14 дней и свежие сигналы. Проекты выше операционки, внутри — по возрасту. Справа — карточка задачи: чей ход, история срока, лента событий. |
| **Люди и нагрузка** | Матрица «приёмка / долг / в работе / недели по срокам». Подпись честно говорит, когда нагрузку нельзя считать часами. |
| **Проекты** | Девять проектов, риск, горизонт сроков, задачи по состоянию, команда, ритм закрытия. |
| **Горизонт** | Сроки на 6 недель вперёд. |
| **Ревизия долга** | Раз в неделю: для каждой старой задачи списать, вернуть в работу или оставить. Список «к закрытию» копируется для Bitrix. |
| **История срезов** | «Машина времени»: что менялось между выгрузками, возможность открыть экран на дату прошлого среза. |
| **ТВ-режим** | Тёмный экран для стены: три сцены по 20 секунд, бегущая лента закрытых задач. |

Определения (всё это же объясняется на экране значком `?`):

- **Приёмка** — исполнитель сдал работу, задача в статусе «Ждёт контроля», ход за постановщиком. Возраст приёмки оценивается по дате последнего изменения. Старше 14 дней — в очередь решений, старше 60 — красная.
- **Старый долг** — давно просроченная и давно не менявшаяся задача (классы `chronic` / `legacy` из модели ниже).
- **Живая задача** — открытая, не в долге и не в приёмке, её трогали за последние 14 дней.
- **Свежесть среза** — до 30 часов свежий, до 72 стареет, дальше экран прямо пишет, что данные устарели.

Решения во «Входящих» (назначить, отложить, эскалировать, готово) хранятся только в dashboard. В Bitrix они ничего не меняют. «Готово» скрывает запись, пока задача не изменится; «позже» — до следующего среза.

### Клавиши

`⌘K` или `/` — поиск по задачам, людям, проектам и команды. `1`–`7` — экраны. `J` / `K` — по очереди, `A` назначить, `S` позже, `E` эскалация, `Enter` готово. Буквы работают и в русской раскладке.

### Написать в Telegram

В карточке задачи (во «Входящих» справа, на телефоне в нижней панели) есть блок **Написать в Telegram**. Сверху кнопки с людьми: первым стоит тот, у кого мяч, дальше исполнитель и постановщик. Ниже четыре заготовки: «Проверить», «Сделать», «Что со сроком?», «Закрываем?». Нужная выбирается сама (приёмка → проверить, просрочка → что со сроком, старый долг → закрываем, иначе сделать). Текст с названием задачи, номером и сроком подставляется в поле, его можно править. Кнопка **Написать …** открывает чат `t.me/<ник>?text=…` с этим текстом в поле ввода и заодно копирует его в буфер. Отправляете вы сами.

Ники вводятся один раз: кнопка **Ники** в боковой панели, команда «Ники сотрудников в Telegram» в поиске (⌘K) или кнопка «Указать ник» в самом блоке. Можно вставить список одним куском, по строке на человека (`Храпугин — @ник`). Ники лежат в хранилище дашборда (браузер или общий сервер), в репозиторий и на GitHub Pages не попадают.

### Эффекты

Точечные цифры показателей, короткие «глитч»-сдвиги, растровое проявление заголовков, поле точек за заголовком, волна точек при переходе. Всё это включается и выключается кнопкой **Эффекты** в боковой панели и по умолчанию выключено у тех, у кого в системе включено «уменьшить движение». Без эффектов цифры остаются обычным текстом.

Шрифт Inter лежит в `assets/fonts/` (лицензия OFL), внешние сервисы шрифтов не подключаются.

### Файлы интерфейса

`briefing.js` — чистая модель экранов (проверяется тестами); `kit.js` — иконки, кольца, чипы, словарь терминов; `fx.js` — эффекты; `views.js`, `views2.js` — экраны; `palette.js` — поиск и команды; `ui.js` — оболочка, карточка задачи, подсказки; `app.js` — маршруты, действия, клавиши.

## Техсовет

Раздел **Техсовет** (боковая панель → «Управление») ведёт реестр поручений, повестку и заседания технического совета. Он работает сам по себе: выгрузка Bitrix не нужна, задачи Bitrix с поручениями не смешиваются.

**Как пользоваться**

1. **Загрузка реестра.** «Загрузка реестра» → выбрать `.xlsx`. Сначала показывается предпросмотр: сколько новых, изменённых, без изменений, какие строки неоднозначны. Пока не нажато «Применить», ничего не меняется. Названия проектов, которые не удалось определить, можно сопоставить вручную; иначе поручения остаются под своим названием.
2. **Реестр.** Фильтры по проекту, ответственному, состоянию, поиск. Карточка поручения: история, блокеры и зависимости, правка полей, «Подтвердить выполнение», «Снять поручение». У каждого поручения постоянный номер `TS-XXXXXX`, он не зависит от строки в Excel.
3. **Повестка.** Собирается из реестра по приоритетам: 1 заблокировано и нужно решение, 2 просрочена контрольная точка, 3 нет однозначного владельца, 4 нет подтверждённого движения, 5 срок близко, 6 прошлое решение без результата. У вопроса есть причина, последствие, вопрос совету и предлагаемое действие; чего в реестре нет, помечено «не хватает данных». Вопросы можно добавлять, двигать и исключать.
4. **Заседание.** «Начать техсовет»: вопросы по проектам, поле решения, ответственный, срок, состояние, «Принять решение», «Подтвердить выполнение», «Создать поручение». Черновик сохраняется сам и переживает обновление страницы. Клавиши: `J` или `→` следующий вопрос, `K` или `←` предыдущий, `D` к полю решения, `Esc` выйти из поля, `Ctrl+Enter` принять (работают и в русской раскладке). «Завершить техсовет» показывает, что запишется, и сохраняет новую версию реестра и сводку.
5. **Заседания.** Все советы с решениями, не рассмотренными вопросами, протоколом и файлами. Следующий совет назначается на неделю позже.
6. **Выгрузка.** «Выгрузить в Excel» на экране реестра: обычные колонки, группировка по проектам, плюс постоянный номер и текущее состояние. Такой файл можно загрузить обратно: дублей не будет.

**Что важно знать**

- Три вещи всегда разделены: черновик (набрано на заседании), принятое решение (нажато «Принять») и подтверждённое выполнение (отдельное явное подтверждение). Статус «выполнено» в файле и отсутствие строки в новом файле поручение не закрывают.
- Пустые ячейки в новом файле ничего не стирают. Исходный текст срока, статуса и блокера сохраняется как в файле; срок различается как точная дата, горизонт («до 14.10»), контрольная точка и условие.
- Если поручение правили руками, а новый файл приносит другое значение, это конфликт: решает человек, файл сохраняется как заметка.
- Данные лежат в отдельных хранилищах (`council`, `councilfiles`), не смешиваются со срезами Bitrix. Локально это IndexedDB, с общим сервером: те же записи на сервере. Запись идёт по ревизиям: если коллега успел изменить поручение, окно покажет оба значения и предложит выбрать.
- Реестр с рабочими данными в репозиторий не попадает: `*.xlsx` в `.gitignore`, файлы и поручения хранятся только в дашборде. Тесты используют вымышленный реестр, который строят сами.

**Файлы:** `xlsx.js` (чтение и запись .xlsx без внешних библиотек), `council.js` (разбор реестра), `council-ops.js` (сопоставление, импорт, правки, блокеры), `council-agenda.js` (повестка, заседание, итоги, выгрузка), `council-store.js` (хранение, ревизии, конфликты), `council-views.js`, `council-meeting.js`, `council-app.js`, `council.css`.

**Следующий этап:** шаблон протокола в DOCX/PDF; подсказки поручений из текста протокола (заготовка есть, без автоприменения); напоминания о контрольных датах; сопоставление поручений с задачами Bitrix по подтверждению человека.

## Кто где

Ежедневный ручной контекст теперь отвечает на физический формат работы сотрудника:

- в офисе;
- на объекте — с выбором одного из 9 активных проектов;
- удалённо;
- в отпуске.

Значения предыдущего дня используются как стартовые при следующей ежедневной загрузке.


## Управленческий Overview

Overview отвечает на состояние отдела в последовательности:

1. **Сегодня** — свежие сигналы, контроль, старый долг, завершения с предыдущего среза.
2. **Что изменилось** — meaningful events между ежедневными snapshots.
3. **Требует внимания** — только актуальные сигналы, без legacy-долга.
4. **Проекты** — активная работа, контроль, сигналы, долг, ближайший срок и последнее движение.
5. **Команда** — физический контекст, текущий фокус, active/control/attention/debt без псевдоточной оценки capacity.
6. **Операционная работа** — задачи ИТО вне девяти основных проектов.
7. **Качество данных** — задачи без срока, работа вне основных проектов, конфликты Project ↔ Parent и незаполненный «Кто где».

При конфликте распознанных проектов родительская/базовая задача является структурным источником истины, а конфликт сохраняется как data-quality сигнал. Существующие snapshots мигрируются при чтении без очистки IndexedDB.
